1. Executive summary
1.1 Where we stand
• Deadline. Midterm presentation on Wednesday 28 October 2026: 20 minutes, graded together with
   executable code and a written report. Today is Saturday 24 October, so there are four working days.
   [VERIFIED]

• What we actually have. One data file (lung_cancer_combined_22457.csv, 22,457 rows, 17 columns)
   and a README that contains only a title. There is no data dictionary, no source link, no licence and no
   second dataset. [VERIFIED]
• What was assumed earlier and is wrong. The brief spoke of several datasets and of 'early detection'.
   There is one file, and its columns are self-reported symptoms and habits, not imaging, biomarkers or
   smoking dose. 'Early detection' is therefore not a claim this data can support. [VERIFIED]
• Rubric. Model training is explicitly not required for the midterm. Points go to data diagnosis, defensible
   cleaning, leakage prevention, EDA with a justified hypothesis test, feature engineering, and the quality of
   explanation. [SOURCED]

1.2 The headline finding (read this twice)
  The apparent signal in the raw file is produced by data-integrity artefacts, not by patients
  In the raw file all 14 binary features are 'significantly' associated with the label (Cramer's V up to 0.144; smoking odds ratio
  1.49, p = 4.5e-30). After removing exact duplicates and the artefact block described below, every association collapses:
  smoking odds ratio 1.00 (95% CI 0.92 to 1.08), largest Cramer's V 0.015, no feature survives multiple-comparison
  correction (smallest BH q = 0.46). A shallow model on the raw file reaches AUC about 0.67 to 0.70; on the de-duplicated
  file it falls to 0.50 (chance). [VERIFIED]

• Artefact 1 - an ordered, duplicated, all-negative block. Rows 1 to 1,455 (patient_id 1 to 1,455) are
   100% negative but contain only 103 distinct feature patterns, repeated 2 to 86 times. Their symptom
   prevalence differs sharply from every later row (e.g. smokers 29% vs 56%; GENDER code 1 in 18% vs
   55%). The first positive label appears at row 1,456. [VERIFIED]
• Artefact 2 - exact duplicates and label conflicts. 2,573 rows duplicate another row exactly (features
   and label). 133 feature patterns carry both labels (315 rows). [VERIFIED]
• Artefact 3 - the identifier leaks. patient_id alone separates the classes with AUC 0.67 because of the
   ordering. It must never be a feature. [VERIFIED]
• Beyond row 1,455 the data behave like independent coin flips. After de-duplication, symptom
   columns are essentially uncorrelated (max |r| = 0.022; 4.4% of 91 pairwise tests significant at 5%, which
   is the chance rate), AGE is almost exactly bell-shaped (skewness -0.01), a PCA has no dominant
   component, and positives and negatives have the same feature profile (e.g. smokers 56.0% vs 56.2%).
   This is consistent with programmatic generation or resampling; it does not prove it. It is also unlike real
   self-reported clinical data, where smoking, age, chronic disease and symptoms are correlated. [VERIFIED]

1.3 What this changes about our strategy
A team that runs a classifier on the raw file will report 'good' accuracy that is an artefact (82% of rows are
positive; shuffled cross-validation with duplicates inflates results further). We do the opposite and win on
exactly the dimensions the rubric rewards: diagnose, justify, prevent leakage, quantify sensitivity,
interpret statistics honestly. This is the integrity-first strategy [DECISION]. It turns an awkward dataset
into a rigorous, memorable midterm and produces a reusable audit pipeline for the rest of the semester.

  Seven decisions to confirm tonight (details in Ch. 5)
  D-01 raw data immutable and checksummed. D-02 integrity-first framing. D-03 primary analysis view = exact duplicates
  removed (view B); C and D are pre-specified sensitivity analyses; A is shown only to quantify the artefact. D-04 patient_id
  is excluded from every feature set. D-05 no model training in the midterm deliverable. D-06 GENDER is reported as a code
  (0/1) until its meaning is verified. D-07 one repository, one Makefile, seed 42, every number regenerated by code.

Phase content required by the rubric. (1) Business understanding: context, problem, focused research
questions, measurable success criteria. (2) Data understanding: sources, rows, columns, types, units, key
variables, initial quality issues. (3) Preprocessing: missing values, duplicates, inconsistent types or
categories, outliers; clean each source and explain integration if there are several; prevent leakage in any
transformation. (4) EDA: descriptive statistics, plots, correlation analysis or heatmaps when appropriate,
relationships between variables, at least one justified statistical hypothesis test with interpretation.
(5) Feature engineering: selection, extraction or creation, encoding, scaling or transformation; justify the
final feature set. (6) Conclusions: evidence-based findings, revisit the questions, limitations, reasonable
future modelling steps without implementing models.
Submission package. Code (runnable notebook(s) or scripts, dependencies and instructions, access to the
data or a documented source); report (structured, six phases, figures and tables with captions,
interpretation, references); presentation (problem, data, preprocessing, key EDA, engineered features,
conclusions, limitations; all members ready for technical questions).

3. Problem and domain primer
3.1 Clinical context [SOURCED]
• Lung cancer is the leading cause of cancer death in the United States. For 2020 an estimated 228,820
   people were diagnosed and 135,720 died; overall five-year survival is 20.5%, while early-stage disease
   has a better prognosis and is more amenable to treatment (USPSTF, JAMA 2021; summarised by Applied
   Radiology).
• Smoking is the most important risk factor and increasing age is the second. The USPSTF 2021
   recommendation (grade B) is annual low-dose CT for adults aged 50 to 80 with at least 20 pack-years who
   currently smoke or quit within the past 15 years. It replaced the 2013 rule (55 to 80 years, 30
   pack-years).
• In the National Lung Screening Trial (NLST), low-dose CT lowered lung-cancer mortality by roughly 15 to
   20% relative to chest X-ray; more than 25% of screened people screened positive but fewer than 10% of
   those positives had or developed cancer (NLST analysis, PMC10002794). False positives are a central cost
   of screening.
• Validated risk models use dose-like smoking variables. PLCOm2012 (Tammemagi et al., NEJM 2013;
   80,375 ever-smokers) uses, among others, age, education, BMI, family history, COPD, smoking status,
   intensity, duration and time since quitting, and was more sensitive than the NLST criteria (41.3% fewer
   lung cancers missed). A yes/no 'SMOKING' flag cannot reproduce that information.

  Why this matters for our framing
  Screening eligibility is defined by age, pack-years and quit time. Our file has none of the last two. Any sentence of the form
  'our model detects lung cancer early' would therefore be unsupported. The defensible scope is: examine whether
  self-reported symptom and lifestyle flags in this file carry reproducible information about the recorded label, and build the
  analysis foundation that a leakage-safe study would need.



3.2 What does the label mean? [OPEN]
The column LUNG_CANCER is coded 0/1. Public descriptions of the related survey dataset say the data were
collected from a website called an 'online lung cancer prediction system', and one paper describes the label
as whether a person 'is suspected of having lung cancer based on symptoms and lifestyle'. If the label came
from a website's own scoring rule, the dataset would measure that rule, not disease. This is a
construct-validity risk: the target may not be a clinical diagnosis. Until the provenance is established we
call it 'the recorded label' and never 'diagnosis' ([DECISION] D-09).

  Why duplicates are harmful and why 'maybe they are real people' is not enough
  Fourteen binary answers and an integer age give about one million possible patterns, so chance collisions among 22,457
  rows are expected to be rare, and are about 600 here. Exact copies of a row inflate n (so p-values shrink,
  'pseudo-replication'), shift class proportions, and, worst, put the same row in both training and test folds ('duplicate
  leakage', one of the eight leakage types in the Kapoor and Narayanan taxonomy). Even if some duplicates were real
  people, we cannot tell which, so the transparent policy is: remove exact copies, and show that conclusions do not depend
  on that choice.

7.1 Hypothesis testing in six sentences
• State a null hypothesis H0 (no association) and an alternative; choose alpha (0.05) before looking.
• Compute a test statistic that measures how far the data are from H0 (chi-square, U, rho).
• The p-value is the probability, if H0 were true, of a statistic at least as extreme as observed. It is not the
   probability that H0 is true and not the size of an effect.
• Type I error = rejecting a true H0 (rate alpha); type II error = missing a real effect (rate beta); power
   = 1 - beta.
• Effect size says how big; confidence interval says how precisely we know it. Report both next to every
   p-value.
• Statistical significance is not practical significance. With n of about 20,000 an association of V =
   0.02 can reach p below 0.05 and still explain 0.04% of variance.

7.3 Power and the minimum detectable effect
For two proportions near p with group sizes n1 and n0, the smallest difference detectable with 80% power at
alpha 0.05 is approximately 2.8 * sqrt(p(1-p)(1/n1 + 1/n0)) (2.8 is 1.96 + 0.84). In view D with p = 0.87, n1 =
11,080, n0 = 8,701 this is about 0.013. Use it to turn 'not significant' into an informative statement: effects
larger than about 1.3 points are very unlikely in this file.

7.4 Multiple comparisons
Test 14 independent true nulls at 5% and the chance of at least one false positive is 1 - 0.9514 = 51%.
Bonferroni divides alpha by the number of tests (very conservative). Benjamini-Hochberg controls the
false discovery rate and is the usual choice for screening many features. In view D the smallest raw p is
0.033; after BH it is 0.46.

7.5 Correlation, association, causation, confounding
• For two 0/1 variables Pearson correlation equals the phi coefficient, and |phi| equals Cramer's V on a
   2x2 table: our heatmap and V values are consistent.
• Correlation does not imply causation. Even a genuine smoking-label association would not show that
   smoking causes the label in this file.
• Confounding by source: if a block of rows has both a different feature distribution and a different label
   rate, the pooled data show an association that vanishes inside each block. That is exactly what removing
   the leading block does (OR 1.49 to 1.00). Always ask: what else differs between the groups I am
   comparing?
• Selection and sampling bias: our file's prevalence (82 to 87%) cannot be generalised to any screening
   population.

12.1 Writing rules
• Claim, evidence, limitation. Every paragraph in sections 3 to 6 states a claim, points to a figure or
   table number with the key number, and says what the evidence does not show.
• Interpretation, not output. The rubric says 'analytical discussion rather than raw outputs': never paste
   a statistic without saying what it means for a research question.
• Numbers only from results.json. Format: counts with thousands separators; proportions with one
   decimal as percentages; p-values in scientific notation when below 0.001; ORs with 95% CI.
• Every figure has a number, a caption that states the question and the takeaway, labelled axes with
   units, and is cited in the text before it appears.
• Citations: numbered or author-year, consistent; paraphrase sources, short quotes only; list the data
   source even if unknown ('provided by course; original provenance not documented').

  Banned and approved phrasing
   • Do not write: 'detect cancer', 'early detection', 'diagnose', 'accurate model', 'predicts cancer', 'proves', 'causes',
     'clinically validated', 'the data is fake', 'AI doctor'.
   • Write: 'recorded label', 'risk indication in a survey file', 'association in this file', 'consistent with', 'we found no evidence
     of', 'effect size', 'research prototype'.
   • For the structure finding: 'statistically consistent with programmatic generation or resampling', never 'the data is
     synthetic' as a fact.

 """Load the raw file read-only, verify its fingerprint and validate the schema."""
 import hashlib
 import pandas as pd
 from config import RAW, EXPECTED, TARGET, ID

 BINARY_12 = ["SMOKING", "YELLOW_FINGERS", "ANXIETY", "PEER_PRESSURE", "CHRONIC_DISEASE", "FATIGUE", "ALLERGY",
              "WHEEZING", "ALCOHOL_CONSUMING", "COUGHING", "SHORTNESS_OF_BREATH", "SWALLOWING_DIFFICULTY", "CHEST_PAIN"]
 FEATURES = ["GENDER", "AGE"] + BINARY_12


 def sha256(path) -> str:
     h = hashlib.sha256()
     with open(path, "rb") as f:
         for chunk in iter(lambda: f.read(1 << 20), b""):
             h.update(chunk)
     return h.hexdigest()


 def validate_schema(df: pd.DataFrame) -> None:
     assert list(df.columns) == [ID] + FEATURES + [TARGET], "unexpected columns/order"
     assert df.shape == (EXPECTED["rows"], EXPECTED["cols"]), f"unexpected shape {df.shape}"
     assert df.isna().sum().sum() == 0, "missing values found"
     assert (df.dtypes == "int64").all(), "non-integer dtype found"
     assert df[ID].is_unique, "patient_id not unique"
     assert set(df["GENDER"]) <= {0, 1} and set(df[TARGET]) <= {0, 1}
     assert all(set(df[c]) <= {1, 2} for c in BINARY_12), "binary flags must be coded 1/2"
     assert df["AGE"].between(18, 110).all(), "implausible AGE"


 def load_raw(verify: bool = True) -> pd.DataFrame:
     if verify:
         assert sha256(RAW).startswith(EXPECTED["sha256_prefix"]), "RAW FILE CHANGED - restore from the original ZIP"
     df = pd.read_csv(RAW)
     validate_schema(df)
     return df

 """Integrity audit: order artefact, duplicates, label conflicts, source shift. Read-only."""
 import json
 import numpy as np
 import pandas as pd
 from scipy import stats
 from config import TARGET, ID, TAB
 from data_io import load_raw, FEATURES

 BIN = [c for c in FEATURES if c != "AGE"]


 def leading_block_end(df: pd.DataFrame) -> int:
     """Index of the first positive label = length of the all-negative leading block."""
     return int(np.argmax(df[TARGET].values == 1))


 def duplicate_report(df: pd.DataFrame) -> dict:
     dup_exact = df.duplicated(subset=FEATURES + [TARGET])
     g = df.groupby(FEATURES)[TARGET].agg(["nunique", "size"])
     return {"dup_rows_features_and_label": int(dup_exact.sum()),
             "dup_rows_features_only": int(df.duplicated(subset=FEATURES).sum()),
             "distinct_patterns": int(len(g)),
             "patterns_seen_more_than_once": int((g["size"] > 1).sum()),
             "max_multiplicity": int(g["size"].max()),
             "conflicting_patterns": int((g["nunique"] > 1).sum()),
             "rows_in_conflicting_patterns": int(g.loc[g["nunique"] > 1, "size"].sum())}


 def source_shift(df: pd.DataFrame, fp: int) -> pd.DataFrame:
     """Cramer's V between leading-block negatives and later negatives, per binary feature."""
     lead, later = df.iloc[:fp], df.iloc[fp:]
     later = later[later[TARGET] == 0]
     rows = []
     for c in BIN:
         tab = pd.crosstab(np.r_[np.zeros(len(lead)), np.ones(len(later))], np.r_[lead[c], later[c]])
         chi2, p, _, _ = stats.chi2_contingency(tab, correction=False)
         rows.append((c, float(np.sqrt(chi2 / tab.values.sum())), float(p)))
     return pd.DataFrame(rows, columns=["feature", "cramers_v", "p"]).sort_values("cramers_v", ascending=False)


 def auc_of_id(df: pd.DataFrame) -> float:
     """How well does the row identifier alone separate the classes? (should be ~0.5 if no leakage)"""
     pos, neg = df.loc[df[TARGET] == 1, ID], df.loc[df[TARGET] == 0, ID]
     return float(stats.mannwhitneyu(pos, neg).statistic / (len(pos) * len(neg)))

src/stats_utils.py
 """Association statistics with effect sizes (never report a p-value alone)."""
 import numpy as np
 import pandas as pd
 from scipy import stats
 from statsmodels.stats.multitest import multipletests
 from config import TARGET, SEED


 def cramers_v(x, y) -> float:
     chi2 = stats.chi2_contingency(pd.crosstab(x, y), correction=False)[0]
     return float(np.sqrt(chi2 / len(x)))


 def odds_ratio_ci(x_bin, y_bin, z=1.96):
     """Odds ratio (exposed vs unexposed) with Wald 95% CI. Inputs are 0/1 arrays."""
     x, y = np.asarray(x_bin), np.asarray(y_bin)
     a, b = ((x == 1) & (y == 1)).sum(), ((x == 1) & (y == 0)).sum()
     c, d = ((x == 0) & (y == 1)).sum(), ((x == 0) & (y == 0)).sum()
     orr = (a * d) / (b * c)
     se = np.sqrt(1 / a + 1 / b + 1 / c + 1 / d)
     return float(orr), float(np.exp(np.log(orr) - z * se)), float(np.exp(np.log(orr) + z * se))


 def permutation_p(x_bin, y_bin, n_perm=5_000, seed=SEED) -> float:
     """Two-sided permutation p-value for the difference in positive rates between x=1 and x=0."""
     rng = np.random.default_rng(seed)
     x, y = np.asarray(x_bin), np.asarray(y_bin)
     obs = y[x == 1].mean() - y[x == 0].mean()
     hits = sum(abs((yp := rng.permutation(y))[x == 1].mean() - yp[x == 0].mean()) >= abs(obs) for _ in range(n_perm))
     return (hits + 1) / (n_perm + 1)


 def feature_family(df: pd.DataFrame, features) -> pd.DataFrame:
     """Chi-square + Cramer's V for each binary feature; Benjamini-Hochberg correction across the family."""
     rows = []
     for c in features:
         chi2, p, _, _ = stats.chi2_contingency(pd.crosstab(df[c], df[TARGET]), correction=False)
         rows.append((c, float(np.sqrt(chi2 / len(df))), float(p)))
     out = pd.DataFrame(rows, columns=["feature", "cramers_v", "p"])
     out["q_BH"] = multipletests(out["p"], method="fdr_bh")[1]
     return out.sort_values("p").reset_index(drop=True)


 def global_lr_test(df: pd.DataFrame, features) -> dict:
     """Likelihood-ratio test of ALL features jointly vs intercept-only logit (inference, not a predictive model)."""
     import statsmodels.api as sm
     m = sm.Logit(df[TARGET], sm.add_constant(df[features].astype(float))).fit(disp=0)
     return {"lr_chi2": float(m.llr), "df": int(m.df_model), "p": float(m.llr_pvalue), "pseudo_r2": float(m.prsquared)}

 """Feature engineering with a written specification. Scalers are FIT on training data only."""
 import numpy as np
 import pandas as pd
 from config import SYMPTOMS_RESP, SYMPTOMS_OTHER, ID
 from data_io import BINARY_12


 def recode_binary(df: pd.DataFrame) -> pd.DataFrame:
     out = df.copy()
     for c in BINARY_12:
         out[c] = (out[c] == 2).astype("int8")                       # 1/2 coding -> 0/1 (2 = YES)
     return out.rename(columns={"GENDER": "GENDER_CODE"})            # sex mapping unverified: never call it male/female


 def fit_age_scaler(train_age: pd.Series) -> dict:
     return {"mean": float(train_age.mean()), "std": float(train_age.std(ddof=0))}


 def add_features(df: pd.DataFrame, age_scaler: dict) -> pd.DataFrame:
     out = recode_binary(df)
     out["AGE_Z"] = (out["AGE"] - age_scaler["mean"]) / age_scaler["std"]
     out["AGE_BAND"] = pd.cut(out["AGE"], [0, 49, 59, 69, 79, 120], labels=["<50", "50-59", "60-69", "70-79", "80+"])
     out["IN_SCREEN_AGE"] = out["AGE"].between(50, 80).astype("int8")                          # USPSTF 2021 age range
     out["RESP_SYMPTOM_COUNT"] = out[SYMPTOMS_RESP].sum(axis=1).astype("int8")                 # 0-4
     out["SYMPTOM_COUNT_ALL"] = out[SYMPTOMS_RESP + SYMPTOMS_OTHER].sum(axis=1).astype("int8") # 0-6
     out["SMOKER_IN_SCREEN_AGE"] = (out["SMOKING"] & out["IN_SCREEN_AGE"]).astype("int8")      # eligibility PROXY only
     return out.drop(columns=[ID], errors="ignore")                                            # identifier never a feature


 FEATURE_SETS = {
     "F0_raw15": ["GENDER_CODE", "AGE"] + BINARY_12,
     "F1_raw_plus_engineered": ["GENDER_CODE", "AGE_Z"] + BINARY_12
     + ["IN_SCREEN_AGE", "RESP_SYMPTOM_COUNT", "SYMPTOM_COUNT_ALL", "SMOKER_IN_SCREEN_AGE"],
     "F2_prior_driven": ["AGE_Z", "SMOKING", "IN_SCREEN_AGE", "RESP_SYMPTOM_COUNT", "SMOKER_IN_SCREEN_AGE"],
 }


 def verify(fe: pd.DataFrame) -> None:

Appendix F. Glossary
 Term                              Meaning

 Association                       Statistical dependence between two variables; not causation.

 Benjamini-Hochberg (BH)           Procedure that controls the false discovery rate across many tests.

 Calibration                       Agreement between predicted risks and observed frequencies.

 Cramer's V                        Effect size 0 to 1 for chi-square tests.

 CLES                              Common-language effect size: P(random positive exceeds random negative).

 Confounding                       A third factor linked to both variables that creates or hides an association.

 Construct validity                Whether a variable measures what it claims to.

 CRISP-DM                          Cross-Industry Standard Process for Data Mining: six phases with feedback loops.

 Data leakage                      Information in training that would not be legitimately available or independent at test time.

 Effect size                       Magnitude of an association independent of sample size.

 FDR                               False discovery rate: expected share of false positives among rejected nulls.

 Grouped CV                        Cross-validation that keeps all rows of a group (here identical patterns) in the same fold.

 IQR rule                          Flags values beyond Q1 - 1.5 IQR or Q3 + 1.5 IQR.

 MCAR/MAR/MNAR                     Missing completely at random / at random given observed data / not at random.

 Odds ratio                        Ratio of odds of the outcome between exposed and unexposed.

 Pack-year                         One pack (20 cigarettes) per day for one year.

 Permutation test                  Significance from shuffling labels to build the null distribution.

 Power                             Probability of detecting a true effect of a given size.

 PR-AUC                            Area under the precision-recall curve; chance level equals prevalence.

 Pseudo-replication                Treating copies of one observation as independent evidence.

 Research prototype                Work for study, not validated for clinical use.

 Sentinel value                    A code such as 999 used to mark missing data.

 TRIPOD+AI                         27-item reporting guideline for prediction-model studies (BMJ 2024).

 VIF                               Variance inflation factor: multicollinearity measure; 1 means none.

 View (A-D)                        One of four pre-specified analysis datasets differing in cleaning policy.
